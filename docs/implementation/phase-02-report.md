# Phase 02 PoC Report

## Execution status

The repository now contains an auditable, offline-safe PoC harness, one
schema-valid artifact per mandatory gate, and unit contracts. External gates
are not falsely marked as passing: Access/D1,
OCI/FFmpeg, Azure, Gemini, YouTube, preview delivery, and Facebook require
credentialed runtimes and are `BLOCKED` until executed on their target hosts.
Facebook has an explicit `FAIL_FALLBACK` decision path for manual post-
approval publication when hidden staging is unavailable.

## Commands

```sh
node scripts/run-poc-gates.mjs artifacts/pocs
python3 -m pytest pocs/manual-ingest pocs/oci-media -q
```

With the local processing-agent environment configured, the focused suites
passed: manual ingest (5 tests) and OCI collector (2 tests). The gate runner
still remains `BLOCKED` until real fixture hashes and credentialed runtime
evidence are supplied.

The runner exits non-zero while mandatory artifacts are missing or blocked.
This is intentional and prevents production enablement before risk gates pass.
Provider artifacts must be generated by their runtime scripts and must contain
the schema fields, a real fixture hash, redaction list, reason, and approved
fallback. The checked-in blocked artifacts provide audit paths only; their
fixture hashes are deterministic non-zero sentinels and are not benchmark
evidence.

## Known limitations

Synthetic media files are not committed; the checked-in manifest intentionally
uses zero hashes as an invalid sentinel. The runner rejects those entries until
the target host generates fixtures and records real SHA-256 values.
Offline tests cover validation and decision boundaries only. No provider
credential, token, account identifier, or absolute filesystem path is stored.
